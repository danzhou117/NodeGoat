# Parity Register

The Python port in `py/` is behavior-preserving: it reproduces the Node application's behavior, including its vulnerabilities and bugs, so that both implementations can run against the same MongoDB data. Every quirk that is preserved on purpose is tagged in the Python source with `# PARITY: <ID>` and recorded here.

Nothing in this register is fixed by the port. A fix is a separate, deliberate change, and the last column says what it would do to data already stored.

| P-010 | Node: `app/data/user-dao.js:33-36`<br>Py: `UserDAO.add_user` | A falsy email (empty string, missing) is not stored at all: the `email` key is absent rather than null or empty. | Readers must treat `email` as optional. | None. ## Known deviations from Node

These are places where the Python code cannot or does not reproduce Node exactly. None of them changes what is written to MongoDB for inputs the application produces.

- JS has both `null` and `undefined`; Python has only `None`. A missing password and an explicit null password are therefore indistinguishable in `validate_login` (P-002).
- `parse_int` returns NaN for arrays, while JS `parseInt([5])` is 5 (P-006).
- The debug `console.log(typeof(id))` in `addUser` is not reproduced.
